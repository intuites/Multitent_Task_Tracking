# Render deployment

`render.yaml` defines two services:

- **taskify** (web, Node 22): `npm ci && npm run build && npm run build:server`, then `node dist-server/server.mjs`. `server.ts` serves `dist/` (with SPA fallback) and the `api/` handlers (`/api/invite`, `/api/cron/tick`) on `$PORT`. Health check: `/healthz`.
- **taskify-tick** (cron, hourly): calls `/api/cron/tick` over Render's private network with the shared `CRON_SECRET` (generated by Render, copied from the web service).

## First deploy
1. Push this repo to GitHub.
2. Render Dashboard → New → Blueprint → pick the repo (or open `https://dashboard.render.com/blueprint/new?repo=<repo URL>`).
3. Fill the variables marked "sync: false": `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (browser-safe), `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, and optionally `EMAIL_PROVIDER_API_KEY`, `EMAIL_FROM`. The `VITE_` values are baked in at build time: after changing them, redeploy.
4. Supabase → Authentication → URL Configuration: set Site URL and add a redirect URL for the Render address (e.g. `https://taskify.onrender.com`), otherwise invite and password-reset links point to localhost.
5. Check `https://<app>/healthz` returns `ok` and `/api/cron/tick` without a header returns 401.

`APP_URL` is optional: links in emails and invites default to Render's `RENDER_EXTERNAL_URL`. Set it only when using a custom domain.

Plans: both services use `starter`. Cron jobs have no free plan; the web service could use `free` but sleeps when idle.
